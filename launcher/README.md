# 岛屿启动器 · Island Launcher 0.10.23

独立的 Windows Minecraft Java 启动器。原生 WPF 山林界面，支持浅色与完整深色配色，无嵌入式浏览器。

0.10.23 修复未扫描到 Zulu 解压版 Java 的问题：识别游戏目录和相邻目录中的 zulu25-win_x64、Zulu JRE、Azul 和带版本号的 JDK 文件夹；补充用户安装目录与 Zulu 32 位注册分支。旧版 Java 检测缓存升级后自动重扫一次，后续继续复用缓存。仍通过实际 java.exe 子进程读取版本、厂商和架构，不凭目录名认定可用。

0.10.22 将外观预览的透明度棋盘格改为白色与浅灰色（#E6E6E6），降低视觉对比，保持原有格子尺寸和透明度参照功能。

0.10.21 完善「上次游玩的地图」卡片的独立外观。右键实际卡片选择「单独设置地图卡片外观」，或在外观页点击「地图卡片设置」，可直接选中该区域。背景色、背景图片、文字颜色、透明度、材质、模糊与蒙层单独保存；文字可自动适配或选择白色、深色、手填 #RRGGBB。修改先预览，保存后应用；重置此区域仅恢复地图卡片，地图名称、游玩信息和存档图标保持不变。

0.10.20 依据前端设计与 UI/UX 技能优化配色和下载交互。正文、辅助文字和边框改用克制的中性色，强调色集中用于按钮、选中和焦点；新增「苔原青」「暮海蓝」「海岛夜色」，共 20 套预设，深色覆盖窗口、表单、弹窗与预览并支持重启恢复。搜索新增名称提示、Ctrl+F、取消按钮和 Esc；加载时保留已有结果并暂时禁止旧选择安装，取消或失败后可重试。按钮不再整体淡化文字作为悬浮反馈，选中行和键盘焦点更清晰；保留「全部」默认版本筛选及安装兼容检查。

0.10.19 修复导入实例被重命名后把实例目录名误当 Minecraft 版本的问题，优先读取 clientVersion 等实际版本元数据。整合包、Mod、光影、资源包的版本搜索筛选默认选择「全部」，下拉框不再使用空白项；选择或切换安装实例不自动填写版本，仍可手动输入或下拉选择。重置筛选恢复「全部」，整合包发布窗口同步显示「全部」；资源安装继续按目标实例的真实版本检查兼容性，无法识别版本时明确提示。

0.10.18 下载中心新增 Mod、光影、资源包三个 Modrinth 入口，支持名称、游戏版本、加载器 / 光影格式、排序与分页。选择已有实例后带入版本和加载器，发布列表只显示适合该实例的版本；可先浏览，安装前必须选择目标。必需前置在确认清单中列出，确认后进入原有下载队列，支持暂停、继续、重试和取消。文件通过 SHA-1 / SHA-512 校验，分别放入实际独立 / 共享目录的 `mods`、`shaderpacks`、`resourcepacks`；不会直接覆盖同名不同内容文件或自动替换已管理的旧版本。光影组件和游戏内的启用操作仍需自行完成。

0.10.17 按紧凑横排展示 Modrinth 整合包：48 像素图标、名称、分类标签、单行简介，以及兼容版本、下载量、相对更新时间与来源。图标异步读取并缓存，缺失或加载失败时显示首字母。搜索和发布窗口的 Minecraft 版本均可输入或下拉选择，留空显示全部。实例卡片动画默认仅在实例列表启用，下载结果使用独立的选中 / 悬浮边框，避免其他列表套用实例动效与双层卡片。介绍网站本次未修改。

0.10.16 集成下载中心：游戏与加载器安装、Modrinth 整合包搜索 / 筛选 / 分页、发布版本选择、本地整合包导入，以及支持暂停、继续、重试、取消和日志的下载队列。每个任务固定加入时的目录、Java、下载源、并发数与可选模组选项；完成后刷新实例列表。暂不支持 CurseForge 整合包与 Mod 在线下载，因为尚未申请 API 访问资格；需要此 API 的 CurseForge 清单导入也会提前说明并停止。本地 Mod JAR 的添加与管理继续可用。

0.10.15 从普通设置中移除 Microsoft 应用 Client ID 输入框及开发者说明。默认使用 ISLAND 自身注册的应用标识，空的旧配置也能直接发起登录；已明确配置的高级覆盖值和已登录账号的刷新配置继续保留。Client ID 是公共标识，不是客户端密钥。

0.10.14 默认使用系统浏览器授权码 + PKCE（S256）登录 Microsoft，登录窗口可切换到备用设备码流程。每次请求使用独立的随机 state、验证器和短时本机回调端口，不需要 client_secret；取消、关闭或超时会释放监听。两种登录与已有账号刷新均经过 Xbox / XSTS 身份一致性校验、Minecraft 游戏授权、entitlements 查询与有效 Java 玩家档案验证，刷新凭据继续通过 Windows DPAPI 加密保存。Azure 应用需在“移动和桌面应用程序”中添加 `http://localhost`，并具备 Minecraft API 访问资格。

0.10.13 保存 Java 检测列表，重新打开启动器或实例设置时直接载入，不必再次点击检测。首次使用、缓存路径失效 / 文件变化、匹配不到兼容版本或点击重新检测时才进行完整扫描；游戏启动前仍单独校验所选 Java。已保存的 Java 被删除后，会显示缺失路径提示并自动重新检测，失效的指定路径改为自动匹配且保存，独立实例保留其他独立设置；启动器打开后才删除 Java，也可在启动时自动恢复。检测记录存放在启动器配置目录的 `java-runtimes.json`，不提交尚未保存的运行设置或外观草稿。有效但版本不兼容的手动选择仍明确报错，兼容检查开关继续保留。

0.10.12 将外观设置中的卡片动效开关改为「卡片动画」，提供关、悬浮跟随（原效果）、轻盈上浮、柔和缩放、弹性跃动、磁吸跟随六种选择，点击即时生效并保存。旧开关自动迁移；选择主题或保存自定义外观时保留所选动画。不同效果分别使用轻微倾斜、位移、缩放、弹性或鼠标方向跟随，移出卡片后平滑复位；关闭或切换效果会清除旧动画与缓存。

0.10.11 修复 HMCL 导入的 GregTech Odyssey 在启动前报「不支持的启动参数：${primary_jar_name}」：按实际解析后的客户端 JAR 文件名展开，兼容中文、空格、重命名及版本继承。同时读取已启用 GTOCore 的入口类版本，避免 Minecraft 1.20.1 的 Java 17 声明掩盖该模组实际的 Java 21 要求；按实例实际的独立 / 共享目录检查，禁用模组不参与判断。自动选择与记住的 Java 均会按新要求校验，手动选择和兼容检查开关沿用原有规则。未改写原整合包配置。

0.10.10 修复游戏运行后无法切换游戏目录的问题。游戏进程启动后，目录标签、收藏、搜索与实例浏览继续可用，也能进入和离开空目录；切换只改变启动器当前浏览位置，不更改正在运行游戏的目录、进程、日志或游玩记录。游戏结束后保留当前浏览目录。准备 / 下载期间仍锁定目录切换，运行中仍防止重复启动和修改目录配置。

0.10.9 将底部启动按钮旁的「管理实例」移至实例卡片右键菜单。菜单包含「实例管理」「Mod 管理」「游戏目录」「存档」「资源包」「光影」，Mod 管理可直接打开。右键时选中并操作对应卡片，文件夹入口使用该实例实际的独立 / 共享目录；缺少子文件夹时创建后打开。双击卡片仍可进入实例管理，键盘菜单键也可打开右键菜单。

0.10.8 修复已安装 GTNH 旧原生库缺少 `path` 时的依赖补全，以及 Cleanroom 被分配 Java 8、已有主库漏入类路径的问题。启动前内存优化改为点击开关即保存；清理时显示小弹窗，等待结束后显示本次可用内存净增量，再启动 Minecraft。启动器记住实例自动选中的 Java，下次仍会探测它的版本与位数；依赖和资源采用文件状态校验缓存，启动日志记录每个准备阶段的耗时，并使用缓冲写入游戏输出。

0.10.7 将地图封面调整为卡片右侧的 64 × 64 圆角正方形，左侧保留地图名称与游玩时间；卡片继续使用配置的背景和材质。封面不再铺满背景或叠加暗色蒙层，缺图时隐藏缩略图并保留文字信息。

0.10.6 在「上次游玩的地图」卡片显示该存档的 `icon.png` 封面，保留地图名与游玩时间；没有封面或图片损坏时使用原有主题背景。全局与独立实例设置新增游戏参数、启动前执行命令、五种 GC 内存管理方式、Java Launch Wrapper / LWJGL Unsafe Agent 禁用开关、高性能显卡偏好与正版登录 SSL 验证开关。现有 Java 列表与重新检测继续使用，保存设置后应用。

0.10.5 在主界面纸娃娃的右键菜单加入「清理内存」，保留动作选择与重置视角。点击后直接复用设置页的清理功能，无需保存；任务进行中菜单与设置按钮一起禁用。结果在纸娃娃旁显示五秒后收起，不跳转页面，设置页与运行日志中也保留结果。需要时 Windows 会请求管理员授权，取消授权会跳过清理。

0.10.4 按参考图重排内存分配：自动配置 / 自定义单选、自定义滑块、系统已使用与游戏预计分配的分段用量条，以及 GB 为单位的已用 / 总量 / 分配 / 可用读数。内存卡片与 Java 卡片分开，启动前内存优化和立即清理保留；全局与独立实例使用同一组控件。自定义内存以 256 MB 步长调整，自动模式禁用滑块并保留之前的自定义值；保存后应用。可见页面每两秒更新系统读数，游戏启动时仍按最新内存重新计算。

0.10.3 在「启动游戏前清理内存」右侧添加「立即清理」。无需勾选自动清理或保存设置即可手动执行，结果与可用内存前后读数显示在当前设置卡片。清理期间按钮显示进度并防止重复点击；取消、权限不足和失败均在原处反馈。运行任务或游戏期间暂不可用，手动清理不会启动游戏或保存未提交的设置。

0.10.2 在「启动器设置 → 全局 Java 与运行内存」新增「启动游戏前清理内存」，默认关闭，点击页面底部「保存设置」后生效。普通启动与一键继续均在补全文件后、分配游戏内存前执行一次：回收系统工作集并清理备用内存。仅短时辅助进程请求 Windows 管理员授权，启动器和游戏保持原权限；取消授权、权限不足或清理失败会记录日志并继续启动，取消整个启动任务则不启动 Java。日志显示各项结果与系统可用内存的前后实时读数，不保证固定释放量或帧率提升。

## 直接使用

解压 `IslandLauncher-0.10.23-win-x64.zip`，双击 `岛屿启动器.exe`。便携包包含 .NET 运行时；**游戏所需的 64 位 Java 需要自行安装**。

1. 在「玩家账号」添加本地玩家，或点击 Microsoft 登录。
2. 在侧栏进入「下载中心」，或点击「添加实例 → 下载游戏」，选择 Minecraft 和加载器并加入下载队列。
3. 选中实例，点击「启动游戏」。右键卡片可打开实例管理、Mod 管理和各类游戏文件夹；双击卡片进入实例管理，Enter 启动选中实例。
4. 「运行日志」显示启动与游戏输出，异常退出后自动打开。运行中可以取消准备任务或结束游戏。

「添加实例」也可连接已有游戏：

- **导入游戏文件夹**：在文件选择器中按 Ctrl 多选 `.minecraft` 根目录，再分别填写显示名称。也可多次导入不同位置的目录。已有文件夹会保留，同一路径不会重复添加；空目录也可以添加，用来安装新实例。
- **导入整合包**：支持下载核心已支持的 `.mrpack`、MultiMC/部分 HMCL 导出 ZIP、MCBBS 和单实例原生 ZIP。Prism 的实例可先导出为支持的整合包格式，再导入。
- **CurseForge 暂未开放**：尚未申请 API 访问资格，暂不支持 CurseForge 整合包与 Mod 在线下载，也不处理需要此 API 的清单 ZIP；会在下载中心、导入提示和 Mod 管理中说明。启动器不会读取环境变量或独立下载器的 CurseForge 凭据。

## 下载中心

- **下载游戏**：原版、Forge、Fabric、NeoForge，支持快照 / 历史版本和新实例名称。新实例不会覆盖同名已有实例。
- **整合包**：使用 Modrinth，可组合名称、Minecraft 版本、加载器、排序及分页。发布窗口提供名称、游戏版本、加载器和发布通道筛选；下载并校验清单后，确认名称和可选模组再加入队列。也可导入本地 `.mrpack` / 支持的 ZIP，或将单个文件拖入启动器。
- **Mod / 光影 / 资源包**：选择要添加资源的已有实例，搜索项目，选择兼容发布并查看安装清单，确认后加入下载队列。Mod 支持 Forge、Fabric、NeoForge、Quilt；Cleanroom 使用 Forge 的筛选身份。光影可筛选 Iris / OptiFine，需实例已有对应组件；资源包不按 Mod 加载器筛选。下载后的光影和资源包在游戏内启用，不修改 `options.txt` 或光影设置。
- **前置与冲突**：递归解析 Modrinth 声明的必需 Mod / 资源包前置，忽略可选项，优先复用已管理且兼容的前置版本；固定版本不兼容、同一项目要求不同版本、外部手动前置或声明冲突会停止并说明。安装记录在实例实际运行目录的 `.island/content.json`；只能识别由此功能管理的项目和声明冲突，不保证任意已有 JAR 或整合包都能兼容。已有同名不同内容文件不覆盖，已管理旧版本需先移除或停用。
- **下载任务**：多条任务依次安装，每张卡片独立显示进度、速度、状态和日志；可暂停、继续、重试或取消，清理已结束项。暂停 / 取消保留有效下载与续传缓存；队列只保留在本次运行中。
- **目标与设置**：新任务使用当前游戏目录和已保存设置。设置中的并行下载数提供 4 / 8 / 16 / 32；修改目录或设置不改变已经排队的任务。完成下载不会将正在浏览的目录切回旧目录。
- **搜索操作**：Ctrl+F 定位搜索并选中文字；名称可以留空直接浏览。搜索期间可点击「取消」或按 Esc，已有结果保持可见，期间不能从旧结果进入安装。失败或取消后可直接重新搜索，空结果提供重试入口。版本仍默认「全部」，切换安装目标不会覆盖手动填写的版本。
- **关闭与启动**：关闭时确认取消未完成任务，并等待安装器退出。正在安装时不能同时启动游戏；游戏准备 / 运行期间不能添加或恢复下载，避免并发修改依赖。
- 任务日志在启动器配置目录下的 `logs/downloads/`。游戏 / 整合包缓存位于所选游戏目录的 `.blockdock/`；Mod、光影和资源包的校验下载缓存位于实际运行目录的 `.island/content-downloads/`。本地 Mod 管理继续可用，在线资源暂不提供自动更新或覆盖升级。

## 玩家皮肤与头像

在「玩家账号」中点击玩家右侧的「配置皮肤」，选择不超过 1 MB 的 64 × 64 或旧版 64 × 32 PNG。支持标准 Classic / 纤细 Slim 模型；旧版皮肤使用标准模型并镜像补齐左臂、左腿。3D 预览包含六面贴图，以及帽子、外套、袖子、裤腿外层，保留透明像素并可单独隐藏外层。头像叠加头部与帽子图层，保存后同步到账号列表与侧栏纸娃娃。皮肤图像随玩家账号保存在启动器配置中，移动或删除原 PNG 不影响已保存头像。取消编辑保留原配置。

预览动作提供站立、行走、奔跑、招手；拖动模型旋转，滚轮缩放，双击或「重置视角」恢复。头部会朝向启动器窗口内的鼠标位置平滑转动，可取消跟随。侧栏纸娃娃也支持这些操作，右键可切换动作。预览动作、外层开关和视角仅用于显示，不修改皮肤文件或游戏动作；后台、最小化或关闭窗口时暂停动画。

- **本地账号**：点击「保存皮肤」保存启动器头像与预览。离线游戏内显示此皮肤需要相应皮肤模组；本版本不会自动安装模组或修改游戏资源。
- **Microsoft 账号**：点击「同步正版皮肤」读取官方档案；点击「保存并上传」会刷新此账号凭据并将皮肤上传到官方 Minecraft Java 档案。恢复默认后保存会重置官方皮肤。上传失败显示原因并保留编辑窗口，可重试或取消。登录 / 启动刷新时会识别官方皮肤变化，并缓存头像；已缓存头像在断网时仍可显示。

实际上传需要可用的正版账号与此启动器自己的 Microsoft Client ID。本次使用模拟 HTTP 验证上传协议和失败 / 取消处理，未使用真实账号执行皮肤更改。

**每个游戏文件夹可分别设置版本隔离。** 点击文件夹标签右侧的齿轮，在「管理游戏目录」中选择：

- **自动检测（默认）**：逐个版本判断。由下载器或启动器安装的实例保持独立；其他版本优先使用版本目录中的模组、存档、配置等数据，版本目录没有数据而根目录有数据时使用根目录，两处都没有数据时使用独立版本目录。空文件夹不作为数据依据。
- **开启**：此文件夹中的所有版本使用 `versions/<实例名称>`，分别保存模组、存档与配置。
- **关闭**：此文件夹中的所有版本使用 `.minecraft` 根目录，共享模组、存档与配置。

切换隔离设置只改变运行位置，不会移动或合并原文件。实例管理显示检测原因和实际游戏目录；启动、模组管理、快捷打开文件夹、最近地图和「一键继续」都使用该目录。共享存档本身无法标识游戏版本，多版本共享时优先结合启动记录或该文件夹的上次选择确定继续游玩的版本。

例如 `E:/NovaEng-CleanroomMC-1.19.2/NovaEng-CleanroomMC/.minecraft` 中，NovaEng 的模组和存档在根目录，而另外两个整合包的数据在各自版本目录；默认自动检测可分别识别这两种布局。

右键实例卡片选择「实例管理」，或双击卡片，开启「使用独立运行设置」后，可将「此版本使用的 Java」设为 **沿用全局设置、自动选择、指定 Java 路径**，也可检测本机 Java。自动选择会忽略全局指定路径，按此版本元数据匹配；留空输入也表示自动选择。设置按游戏文件夹和版本分别保存，同名版本互不影响。

## 全局与独立运行设置

**启动前内存优化**：在内存卡片勾选「启动游戏前进行内存优化」，点击即保存，只保存此开关，不提交其他运行设置草稿。准备好依赖及启动前命令后，等待管理员清理辅助进程结束，显示本次结果，再按最新可用量分配内存并启动 Minecraft。小弹窗显示进度和五秒结果；设置页及本次启动日志也保留结果。「本次释放」表示清理前后系统可用物理内存的非负净增量，后台程序和原本即可复用的备用页会影响读数；不伪造固定释放量。拒绝授权 / 权限不足不会显示释放成功，取消整个启动任务则不会启动游戏。

「启动器设置」中的 Java、内存与 JVM 参数作为全局默认值。管理实例中关闭「使用独立运行设置」会清除这个版本的运行覆盖，之后沿用最新全局设置；开启后保存这个版本自己的 Java、内存、JVM、游戏参数及兼容选项。独立设置不会随全局 JVM 或内存的修改而变化，Java 也可单独选择继续沿用全局。已有版本的独立 Java / 内存设置会保留，并迁移为一组独立运行设置。

- **自动配置**：启动前读取 Windows 总内存与当前可用物理内存，结合实际游戏目录内启用的模组数量估算最大堆内存。无模组基础目标为 2 GB；1–100、101–250、更多模组的目标分别为 4、6、8 GB，再按可用内存和系统预留空间降低，按 256 MB 取整。32 位 Java 的自动上限为 1 GB。设置页显示预计分配，启动时重新计算；滑块在自动模式下禁用。
- **自定义**：选择后拖动滑块，也可用方向键按 256 MB 调整，保存后生效。常规滑块上限按本机总内存设置，最多 64 GB；已有配置中的较高上限会保留。切回自动不会丢失自定义草稿。底部显示系统已用 / 总量及游戏分配 / 可用量，过量分配只在用量条中绘制可用部分，不伪造额外物理内存。
- **不添加默认的 Java 虚拟机参数**：跳过启动器默认的 UTF-8 编码参数；启动必需的类路径、原生库、版本元数据与内存参数继续保留。
- **不自动添加 Java 虚拟机优化参数**：停用启动器的 GC 预设及优化参数，保留版本元数据和自定义参数。启用预设时会替换元数据中冲突的 GC 选择，自定义 JVM 中指定的 GC 优先。没有保证所有游戏或 Java 版本都因此提升性能。
- **不检查 Java 虚拟机与游戏的兼容性**：手动指定 Java 时，跳过最低版本与位数检查，仍验证程序能否运行；自动选择继续按游戏元数据匹配。该设置不会使不兼容的 Java 获得运行游戏的能力。
- **Java 虚拟机参数**：支持空格、换行及单 / 双引号；包含空格的路径须加引号。自定义参数放在生成参数之后；自定义 `-Xmx` / `-Xms` 优先于内存界面中的值。不会经由命令行 shell 执行。
- **游戏参数**：追加到游戏主类之后，支持引号包住含空格的参数，与 JVM 参数分别保存；不会经由 shell 执行。
- **启动前执行命令**：留空不执行。在实际游戏目录中通过 Windows `cmd` 执行一行命令，等待成功结束后再清理 / 分配内存并启动游戏。非零退出码会停止启动；取消任务会终止该命令的进程树。命令输出显示在运行日志中。
- **内存管理**：提供「尽量使用 ZGC」「尽量使用分代 ZGC」「标准 G1GC」「调优 G1GC」「不指定（可自定义）」。ZGC 从 Java 15 起使用，旧版本回退 G1；分代 ZGC 在 Java 21–22 添加启用标志，Java 23 起使用其默认分代实现。标准 G1 仅指定收集器；调优 G1 另加 200 ms 暂停目标及并行引用处理，保留手动设置的相应参数。不指定时保留版本及自定义参数，使用 Java 自身默认值。
- **禁用 Java Launch Wrapper / LWJGL Unsafe Agent**：取消对应的自动兼容修复。编码包装器仅在 Windows 系统代码页为 UTF-8、Java 6–18 时启用；LWJGL Agent 仅在 Java 25+、LWJGL 3.4.0–3.4.1 且非 Forge 时启用。组件随启动器内置，按需校验并释放至游戏根目录的 `.island/patches/`，无需临时联网下载。
- **使用高性能显卡**：默认关闭。开启后在游戏运行期间请求所选 Java 使用 Windows 高性能图形偏好，正常结束或取消后恢复原值；期间用户改动的值会保留。此偏好按 Java 可执行文件作用，其他使用同一 Java 的进程也可能受影响；最终 GPU 由系统与驱动选择，启动器异常终止时可能来不及恢复。
- **在正版登录时验证 SSL 证书**：默认开启，旧配置升级也保持验证。关闭后只对 Microsoft / Xbox / Minecraft 登录服务放宽证书检查，供证书兼容排查使用，会降低这些登录连接的安全性；皮肤下载及游戏文件下载保留原验证。
- **兼容旧版本的内存选项**：可设置初始堆内存 `Xms`，以及仅供 Java 7 及更早版本使用的 `MaxPermSize`。Java 8 起不会自动添加已废弃的永久代参数。此区域默认折叠。

## 已安装 GTNH / Cleanroom 与启动检查

通过「添加实例 → 导入游戏文件夹」连接已经由 HMCL 等启动器安装好的 `.minecraft` 根目录。本轮以用户提供的 GT New Horizons 2.8.4 和 NovaEng-CleanroomMC 目录为参考，保留其完整的启动入口、JVM 参数、库及版本隔离配置。GTNH / LWJGL3ify 的系统类加载器和模块开放参数不会被替换为普通 Forge 参数；仅修复缺少原生库路径字段时的 Maven 路径计算。Cleanroom / Foundation 至少选择 Java 21，并读取 Foundation 主类的 class 版本提高实际要求；元数据要求更高版本时继续遵守该要求。已有 `downloads: {}` 的本地 Cleanroom 主库也会加入类路径。

首次启动仍需完整检查文件。之后将已通过哈希校验的文件长度、修改时间及预期校验值记录在游戏根目录 `.island/verified-files.json`；三者一致时跳过重复哈希读取，文件或元数据变化后重新校验。删除此缓存可强制下次完整检查。缺失、损坏文件仍按元数据补全，本地专用兼容库缺失时给出重新导入完整目录的提示。实例自动选中的 Java 路径是技术缓存，不会变成手动 Java 覆盖；每次复用仍实际探测，失效时重新搜索。「重新检测」会刷新环境并清除记住的自动选择。

本轮覆盖已安装目录的启动兼容，尚未扩展带自定义补丁组件的原始 Prism ZIP 导入。真实整合包加载速度还取决于模组、Java、磁盘和可用内存；准备阶段时间不等于整包进入主菜单的时间。

## 外观与模组管理

在「启动器设置」点击「打开外观设置」，进入独立页面。上方是可点击的启动器预览，下方显示所选区域的设置；预览保持固定，下面的设置独立滚动。顶部「返回设置」回到运行设置，「保存外观设置」始终可见。点击左侧导航也可离开此页面。

直接点击预览中的 **窗口外框与背景、左侧导航模块、右侧内容模块、上次游玩卡片、实例卡片、设置与账号卡片、底部启动栏、上次游玩的地图卡片**。选中区域显示边框，下方显示名称与对应控件。点击外圈或顶部栏可选择最大的窗口背景；右侧内容模块是内层独立背景，内部的卡片仍可分别选择。地图小卡片可单独点击；点击任意实例卡片会编辑实例卡片这一类区域。材质用三个平铺按钮选择：纯色 / 图片、高斯模糊、液态玻璃。每个区域分别保存材质、背景颜色与不透明度。勾选「跟随主题颜色」使用当前主题底色，关闭后可输入自己的 `#RRGGBB`；自定义深色背景会调整该区域的文字和输入控件颜色。

点击预览背景时还会显示自定义主题色与窗口整体不透明度。20 种预设主题位于启动器设置页的「外观设置」卡片，点击即可切换整套外观并保存，包含「苔原青」「暮海蓝」、完整深色的「海岛夜色」和内置花瓣背景的「流光玻璃」；隐藏纸娃娃开关同样即时保存。选择普通配色会清除当前使用的背景图片与材质配置，恢复这套配色的纯色外观，图片文件保留。「流光玻璃」的背景随程序内置，首次使用复制到配置目录，重启后继续使用；不会替换账号皮肤。外观预览中的自定义微调仍需点击保存后应用。可输入 `#RRGGBB` 自定义颜色，修改时仅更新上方预览与选色样本；保存成功后应用于实际按钮、收藏、导航、侧栏与弹窗。明亮主题自动使用深色按钮文字。外观页面没有下拉菜单。

- **地图卡片**：右键主界面「上次游玩的地图」卡片，选择「单独设置地图卡片外观」；也可在外观页点击「地图卡片设置」或直接点击预览中的小卡片。背景色、图片、不透明度、三种材质与文字颜色独立设置。文字默认自动适配背景，可选白色、深色或输入十六进制颜色；修改先预览，保存后应用。「重置此区域」只恢复这张卡片，不改动外层卡片、存档名称或地图图标。
- **背景图片**：主背景、上次游玩与地图卡片可分别选择 PNG / JPEG / BMP。图片按覆盖区域裁切，支持蒙层浓度调节。单张不超过 30 MB、6400 万像素，单边不超过 16384；显示解码最大边约 1920，避免大图占用过多内存。保存时复制原图到启动器配置目录的 `Backgrounds/`，相同图片共用文件，移动原图不影响已保存背景。图片缺失、损坏或不可读时使用主题底色 / 默认山林插画；点击「使用纯色」移除该区域自定义图片，上次游玩同时隐藏默认插画。重置该区域可恢复插画。
- **纯色 / 图片与高斯模糊**：分别显示原始图片或柔化后的背景图片。0.10 起不再提供亚克力和云母，旧设置迁移为高斯模糊。
- **液态玻璃**：取样实际的底层材质背景，中央磨砂透色，圆角边缘进行局部折射，并叠加方向反光和细边缘。可调整模糊、蒙层浓度与背景不透明度，文字不参与模糊。纯色底层不会凭空产生图案；有色彩或纹理的背景更容易看清折射。背景取样不包含前景文字或模型，不读取桌面；父级不透明底色会遮住更底层的图片。结果按区域缓存，皮肤动画与鼠标移动不触发重新取样。
- **窗口材质**：三种材质均由应用内绘制，窗口整体透明度仍独立控制。启动时清理旧版系统背景，保留窗口圆角与缩放。
- **背景不透明度**：0–100%，仅影响该区域的背景绘制，文字与图标不跟随变淡，也不参与模糊。**窗口整体不透明度**范围 40–100%，编辑时只让预览小窗口整体变淡，保存后才调整实际主窗口对桌面的透明度，调整尺寸后继续保持。100% 为完全不透明。
- **保存与重置**：修改时只更新上方小窗口，实际启动器保留上次保存的外观。点击「保存外观设置」可应用并保存主题和背景，不需要填写 Java 等运行设置；普通「保存设置」也会应用并保存外观。保存失败保留原来的实际外观。「重置此区域」只还原当前预览区域，「重置全部背景与材质」将预览恢复默认不透明界面，之后保存生效。切换页面保留未保存草稿，关闭窗口后丢弃。

实例卡片按可用宽度均匀分列，窗口大小改变时自动调整列数和宽度。点击卡片右上角的星形按钮即可收藏 / 取消收藏，无需进入实例设置；「收藏」页取消收藏后会即时移除该卡片，不影响原游戏文件。

在「管理实例」中点击「管理模组」，进入可调整窗口大小的模组管理窗口。文件名列随窗口宽度伸缩，长文件名显示省略号，悬停可查看完整路径。支持按文件名搜索、筛选全部 / 已启用 / 已停用，以及 Ctrl / Shift 多选后批量启用或停用；操作通过改名保留模组文件，已有同名文件不会被覆盖。共享目录中的模组依然按共享目录规则操作。

## 文件夹与上次游玩

实例列表上方的标签依次为 **收藏、文件夹1、文件夹2……**。点击文件夹名称显示该目录下的实例；标签较多时可横向滚动。「收藏」汇总全部已添加目录中的收藏实例。每个目录保留自己的实例显示名称、收藏、Java、内存与上次选择，同名版本也分别保存。

点击标签行右侧的齿轮可以重新命名目录或设置版本隔离；名称只用于启动器显示。创建实例、导入整合包安装到当前游戏目录；从收藏页创建时使用最后选中的文件夹。设置页显示该安装位置。

顶部「上次游玩」在全部已添加目录中查找最近记录，并读取实际游戏运行目录 `saves/<地图文件夹>/level.dat` 中的地图名称及游玩时间，支持中文和表情字符。没有记录时显示空态。「一键继续」会切换到对应文件夹并启动该实例；版本元数据支持 Minecraft Quick Play 时直接进入对应单人地图，较旧版本正常启动后可在单人游戏中继续。地图信息来自本地单人存档，不包含多人服务器记录。

旧版配置会自动迁移为一个「默认目录」标签，已有账号、实例设置和当前路径继续使用。

## 功能

- 原版、Fabric、Forge、NeoForge 安装；正式版、快照与历史版本列表。
- 多个隔离实例，搜索、收藏、显示名称、最近游玩时间和累计时长记录。
- 本地实例图标兼容 `icon.png`、`instance.png`、`PCL/Logo.png` 等下载核心已支持的位置。
- 自动匹配本机 Java，手动选择 Java，全局/单版本 Java 与内存设置。
- 本地离线账号；Microsoft 浏览器 PKCE 登录与备用设备码、Xbox / Minecraft 授权和启动前刷新。
- 版本 JSON 继承、Maven 依赖覆盖、现代/旧版参数、Windows 规则和 natives 解压。
- 启动前校验与修复公开依赖和资源；完整文件可本地复用，联网账号仍需在线验证。
- 模组文件添加、启用/停用；快捷打开存档、资源包、光影和实例目录。
- 中文/空格路径；游戏标准输出和错误输出合并保存；Mojang XML 日志转换为可读文本。
- 取消安装、结束游戏、异常退出码、关闭时等待任务退出；凭据不会写入启动日志。

目前为早期版本，**不是 Prism 的完整功能复刻**。尚无在线资源自动更新、Java 自动下载、实例导出、Quilt / OptiFine 加载器安装和第三方认证。Forge/NeoForge 的安装复用已有下载核心，新增启动链的真实图形验证覆盖原版和 Fabric 1.21.1；其他组合需按具体整合包进一步验证。

## Microsoft 正版登录

进入「玩家账号」点击 Microsoft 登录即可使用启动器内置的 ISLAND 应用标识，无需在普通设置中填写 Client ID。该标识是公开的应用身份，不是密码或客户端密钥。正版服务的实际可用性仍取决于应用的 Minecraft Services API 访问资格。

默认打开系统浏览器，使用授权码 + PKCE S256，也可在登录窗口切换设备码流程。刷新凭据由当前 Windows 用户的 DPAPI 加密，保存在独立设置文件；访问令牌仅在内存中用于当次启动。

开发者配置：在 Azure / Microsoft Entra 的应用注册 → 身份验证 → 添加平台中，选择“移动和桌面应用程序”，添加 `http://localhost`。本机随机端口按微软的 localhost 规则匹配；设备码还需允许公共客户端流程。不需要客户端密钥。高级用户可在退出启动器后修改配置文件的 `MicrosoftClientId` 以覆盖内置值；留空使用内置配置。普通设置保存不会清除已有覆盖，已登录账号继续使用其原有应用标识刷新。

两种流程和已有账号刷新均校验 Xbox / XSTS 用户一致性，依次调用 Minecraft `authentication/login_with_xbox`、`entitlements/mcstore` 和 `minecraft/profile`。与 HMCL 一样，不将商店返回的空 items 列表单独视为无资格，而是继续要求有效的 Java 玩家档案，避免误拒订阅用户；资格接口失败或档案不可用时不会添加账号。

API 访问资格尚未具备时，可使用本地离线账号游玩已安装实例。离线账号无法登录要求正版认证的在线服务器。本次通过真实本机 HTTP 回调和模拟远端服务验证协议、取消及失败处理，未使用真人 Microsoft 账号进行完整登录，也没有修改 Azure 应用配置。

## 与下载器的分离

| 项目 | 岛屿启动器 | 方块下载器 |
| --- | --- | --- |
| EXE | `launcher/dist/win-x64/岛屿启动器.exe` | 原有 `dist/win-x64/方块下载器.exe` |
| 解决方案 | `launcher/Island.sln` | 原有 `BlockDock.sln` |
| 构建入口 | `launcher/build.ps1` | 原有 `build.ps1` |
| 配置、账号、日志 | `%LOCALAPPDATA%/IslandLauncher/` | `%LOCALAPPDATA%/BlockDock/` |
| 默认游戏目录 | 启动器旁的 `IslandData/.minecraft` | 下载器自己的设置 |
| 运行依赖 | 独立便携包 | 独立便携包 |

源码编译时复用工作空间中 `src/BlockDock.Core` 的公开安装与 Java 检测能力，并以源文件链接复用独立下载器的任务队列 / 任务模型；发布后的启动器单独运行，不需要下载器 EXE。下载核心在所选游戏目录内使用 `.blockdock` 安装缓存；启动器专用临时原生库位于 `.island/natives`。只有手动连接同一游戏目录时，两者才共用该目录的游戏文件。

## 开发与构建

Windows 10/11、.NET 8 SDK，无新增 NuGet 第三方依赖。真实 JVM 测试需要本机 JDK（含 `javac.exe`）；UI 测试需要 JDK 17 或更高，可编译为 Java 8 目标。

```powershell
dotnet build launcher/Island.sln -c Release
dotnet run --project launcher/tests/Island.Tests -c Release
dotnet run --project launcher/tests/Island.App.Tests -c Release
./launcher/build.ps1
```

联网检查版本接口：

```powershell
dotnet run --project launcher/tests/Island.Tests -c Release -- --network
dotnet run --project launcher/tests/Island.App.Tests -c Release -- --network
```

真实安装和图形启动检查会下载游戏文件，使用专门的测试目录：

```powershell
dotnet run --project launcher/tests/Island.Tests -c Release -- --install F:/IslandTest/.minecraft 1.21.1
dotnet run --project launcher/tests/Island.Tests -c Release -- --install F:/IslandTest/.minecraft 1.21.1 --loader Fabric
dotnet run --project launcher/tools/Island.Smoke -c Release -- F:/IslandTest/.minecraft 1.21.1-Island F:/IslandTest/vanilla.log
dotnet run --project launcher/tools/Island.Smoke -c Release -- F:/IslandTest/.minecraft 1.21.1-Fabric-Island F:/IslandTest/fabric.log
```

烟雾工具使用自己的离线测试玩家，不创建存档，隐藏测试游戏窗口，确认渲染器初始化并加载纹理图集后结束它启动的进程。同名安装已存在时拒绝覆盖。

图形界面离屏截图（`--data-dir` 指定独立的配置测试目录）：

```powershell
./launcher/dist/win-x64/岛屿启动器.exe --capture F:/IslandShots --data-dir F:/IslandCaptureState
```
